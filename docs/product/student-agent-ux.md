# HOOPSHAKE 学生端 Agent 产品使用逻辑

`v1.0 · 2026-08-13 · 产品设计`

补技术参考手册 §10.1 只列了两个学生页面("聊天页""我的训练情况")却没有使用流程的空白。本篇从学生视角把**从第一次登录到日常使用**的完整产品逻辑串起来,每个环节标清对应的后端能力与降级行为。

对应技术能力:`../agent/cloud-agent-api.md`(端点)、`../agent/agent-system-design.md`(Agent 行为)。产品定位不变:**不打分、不排名,只做动作反馈指导与训练原理问答**(技术 §一)。

---

## 1. 角色与目标

学生端只有两类事要做,对应两个页面:

| 页面 | 学生想解决的问题 | 后端 |
|---|---|---|
| **聊天页**(主) | "我这个动作为什么不对/怎么改?" | Director → Skill Coach(ReAct,SSE) |
| **我的训练情况** | "我最近练得怎么样?哪块在进步?" | §4 训练数据 + Skill Coach 概览 |

产品主张:聊天页是入口,训练情况页是佐证。两者共享同一批结论数据(§4),所以 Agent 说的话和数据页看到的能对上——这是可信度的基础。

---

## 2. 首次进入:激活闸(不可跳过)

学生账号由教师建档产生(Cloud §5.7 导入或 §6.1 单建),初始状态 `PENDING_ACTIVATION`。**未激活的学生几乎什么都做不了**——除激活相关端点外一律 `40311`(Cloud §1.5),对话页也进不去。

```
初始密码登录(学号/初始密码)
  → 命中 40311 → 前端不弹"无权限",引导进激活流程(Cloud §1.5 为此单开 40311)
  → §2.6 绑手机 + 改密 → status: PENDING_ACTIVATION → ACTIVE
  → 回到聊天页,可用
```

**产品要点**:40311 的处置是"去激活",不是"报错"。前端必须区分它与 40300/40100(Cloud §1.5 单开此码正是为此)。激活前的空档期,教师端名单页会把该生标为未激活(便于催)。

## 3. 聊天页:核心使用回路

### 3.1 三种进入姿势(决定 Agent 的"视野")

学生可以从三个地方发起对话,决定了会话是否**锚定训练**,进而决定 Agent 的 Mode 与能力(设计 §5.1):

| 进入姿势 | 锚定 | Mode | Agent 视野 |
|---|---|---|---|
| 聊天页直接问("投篮为什么要屈膝") | 无 | `STUDENT_OPEN` | 通用原理 + 本人历史(轻) |
| 从"我的训练情况"某次课点"问一下" | `trainingSessionId` | `STUDENT_STRUCTURED` | 聚焦这次课的结论 + 更高档位 |
| 从某个动作片段点"这次怎么样" | `trainingSessionId`(+clip 上下文) | `STUDENT_STRUCTURED` | 聚焦单次动作 |

**产品价值**:同一个"我投篮怎么样"的问题,从训练页锚定进来,Agent 直接读这次课的 `session_aggregate`/`instant_feedback` 给具体答复;从空白聊天进来,则先问"你想聊哪次训练"或给泛化建议。锚定 = 少一轮澄清。

### 3.2 一次提问的可见过程(SSE,设计 §3.1 / API §3.4)

学生发出问题后,屏幕上依次出现:

```
① 气泡建立(meta)
② "正在查看你最近5次投篮…"(tool,中文 label,不是 GetRecentClips)
③ 逐字回答(delta)
④ 结束 + 2~3 条建议追问(done.suggestions)
```

- **工具轨迹是产品特性不是调试信息**:让学生看到"AI 真的在看我的数据",而不是凭空生成。`label` 必须是人话(设计 §7.5)。
- **建议追问**降低"不知道该问什么"的门槛,尤其新用户。
- **可随时点停止**(interrupt,API §3.6),已生成的话保留。

### 3.3 Skill Coach 的回答风格(设计 §4.4)

产品上要求 Skill Coach 做到"双路数据结合"(技术 §4.4)——把课中即时反馈(2D 糙提示)和课后 3D 评分连起来说:

> "上课时大屏提示过你**肘外翻**(即时反馈),课后 3D 复核确认你的**肘角偏了约 20°**(结论层评分)。改法是……(RAG 召回的纠正练习)。"

这三句分别来自 `instant_feedback` 工具、`GetActionDetail` 工具、`SearchCheckpointKnowledge`(RAG)。产品价值:比单说"你肘外翻"有说服力得多——有当时的、有事后的、有怎么练的。

### 3.4 关键场景的额外把关(Reflection,设计 §4.4)

学生无感,但后端在这些场景会多做一次自评再回(成本 +20% 换质量,技术 §4.4):

- 涉**损伤风险**("我膝盖疼")——最重要,宁可慢一点也要稳。
- 长输出(>500 字)、用户表达不满、涉训练计划修改。
- 简单查询/闲聊/看历史**不触发**(省成本)。

产品体现:损伤类问题回答更稳、更倾向"建议休息/就医"而非硬给训练动作。

## 4. "我的训练情况"页

数据来自 §4 端点,是聊天页的佐证面板,也是独立可用的自查页。

| 区块 | 端点 | 学生看到 |
|---|---|---|
| 概览(本周训练/命中率/本阶段重点) | `4.1 overview` | 一眼看本周练了几次、重点检查点较上周改善多少 |
| 训练课列表 | `4.2 sessions` | 每次课的关键改善标签 |
| 单次课详情 + 动作片段 | `4.3/4.4` | 各动作统计、每次出手的评分 |
| 单个动作完整视图(含 3D 回放) | `4.5 clip` | `motionDataUrl` 拉 MinIO 逐帧做 3D 回放 |
| 即时反馈流水 | `4.6 feedback` | 课中大屏提示过什么 |
| 进步趋势 | `4.7 trend` | 某动作某指标的时间曲线 |

**每个区块都能"问一下"**:点任意卡片可带锚定跳到聊天页(§3.1),把"看到数据"无缝转成"问 Agent"。这是两个页面的黏合点。

## 5. 空状态与降级(产品必须设计,否则一片空白)

| 情况 | 现象 | 产品处理 |
|---|---|---|
| 新生,还没上过课 | §4 全空 | 概览页给"还没有训练数据,上完第一节课就能看到";聊天页仍可问原理(STUDENT_OPEN 通用知识) |
| 课上了但 `status < SCORED` | 数据不全 | 透出"评分处理中",不报错(API §4);Agent 说"这次课还在处理,先看上次" |
| 词表未上线(审计 A1) | RAG 召回空 | Skill Coach **降级**:只用结论层工具 + 通用知识,不硬接空 RAG(API 附注) |
| LLM 不可用 | 对话失败 | 降级链兜底话术 + `50310`,训练数据页**照常可用**(不依赖 LLM) |
| Token 预算耗尽 | 长对话中断 | 流内 `42910`,已生成保留;提示"今天聊得有点多,已生成的可以先看" |
| ReID 认错人(数据污染) | 别人的动作进了我的档案 | 一期无学生自助纠错(教师端 §6.6 🚧);产品先不暴露,靠教师纠错通道 |

**降级原则(继承边缘设计哲学)**:AI 挂了,查数据不能跟着挂。训练数据页(§4)与对话(§3)解耦,LLM 不可用时前者照常。这与 edge "断网照常上课"(Edge §10)同源——**核心查看能力不吊死在 AI 可用性上**。

## 6. 数据边界(学生只能看到自己)

产品承诺:**学生永远看不到别人的数据**,三道闸(设计 §0):

1. web 鉴权:token 里的 studentId 就是数据主体,请求体传别人 id 无效。
2. Agent 工具:studentId 由 Hook 从会话强制注入,LLM 编造入参也访问不到他人(设计 §5.3)。
3. 事后审计:任何越权尝试进 `audit_log`(`TOOL_DENY`),一查即现(设计 §8)。

对学生不可见,但产品上意味着:**可以放心让 Agent"读我的所有训练数据"而不担心串号**——这是让学生敢用的前提。

---

## 7. 隐私与内容边界

- **PII 脱敏**:出站给 LLM 的 prompt 里姓名等被占位替换,回来还原(设计 §5.2),学生数据不进第三方模型日志。
- **不打分不排名**(技术 §一):Agent 不说"你全班第几",只说"你自己较上次的变化"。产品文案统一口径:进步是跟自己比。
- **家长入口**:阶段一不开放(技术 §4.6),`/api/parent/**` 恒 501,学生端不出现任何"分享给家长"的入口(避免许诺未实现能力)。

## 8. 阶段一学生端交付清单

| 能力 | 状态 | 依赖 |
|---|---|---|
| 激活流程(40311 引导) | ✅ 已实现(Cloud §2.6) | — |
| 聊天页(Skill Coach,SSE,工具轨迹) | 待建 | Harness + 词表(A1) |
| 我的训练情况(§4 六个端点) | 待建(DTO 已在) | ingest 有数据 |
| 建议追问 / 中断 / 会话管理 | 待建 | §3 端点 |
| RAG 召回(检查点知识) | 待建,可后接 | §12 词表落地 |
| ReID 学生自助纠错 | ❌ 一期不做 | 教师端 §6.6 🚧 |

**最小可用**:激活 + 训练数据页 + Skill Coach(结论层工具,先不接 RAG)。RAG 随词表补齐后无缝增强,不阻塞学生端上线。
